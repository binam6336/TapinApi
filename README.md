# TapinApi

داشبورد فارسی تست API پست، تیپاکس، قطاربار و ووکامرس با یک فرانت‌اند و یک سرور. پست ۳۶ مسیر، تیپاکس ۱۸ مسیر و قطاربار ۱۵ مسیر دارند. نمونه‌های JSON از ابزارهای اولیه آمده‌اند و قبل از ارسال قابل ویرایش‌اند.

## راه‌اندازی

به Node.js 24 یا بالاتر و یک دیتابیس MySQL یا MariaDB نیاز دارید. ابتدا دیتابیس و کاربر آن را بسازید. برنامه جدول اتصال‌ها را هنگام راه‌اندازی ایجاد می‌کند.

```sh
npm ci
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

خروجی فرمان آخر را در `DATABASE_KEY` بگذارید و برای `DASHBOARD_PASSWORD` رمز حداقل ۱۲ کاراکتری تعیین کنید. تنظیمات اتصال دیتابیس را در `DB_HOST`، `DB_PORT`، `DB_NAME`، `DB_USER` و `DB_PASS` وارد کنید. `DB_TIMEZONE` به‌طور پیش‌فرض `+03:30` است. سپس اجرا کنید.

```sh
npm start
```

آدرس داشبورد را در `BASE_URL` تنظیم کنید. مقدار پیش‌فرض محلی `http://127.0.0.1:3000/` است. همان آدرس را مستقیم در مرورگر باز کنید و با `DASHBOARD_USER` و `DASHBOARD_PASSWORD` وارد شوید.

### باز کردن داشبورد از روت دامنه

آدرس دامنه را مانند `BASE_URL=https://dashboard.example.com/` تنظیم کنید و فرایند `npm start` را روی میزبان اجرا کنید. `HOST` و `PORT` آدرس شنود Node را تعیین می‌کنند.

- **Apache**. فایل مخفی `.htaccess` همراه پروژه را در روت پروژه نگه دارید. ماژول‌های `mod_rewrite`، `mod_proxy` و `mod_proxy_http` باید فعال باشند و برای این دایرکتوری `AllowOverride FileInfo Indexes` مجاز باشد. قانون روت، فایل‌های فرانت‌اند و API را به Node روی `127.0.0.1:3000` می‌فرستد. اگر پورت Node را تغییر دادید، مقصد قانون را هم تغییر دهید.
- **Nginx**. در تنظیمات دامنه، درخواست‌ها را با `location / { proxy_pass http://127.0.0.1:3000; }` به Node بفرستید. برای نصب در زیرمسیر مانند `/tapin/`، همان زیرمسیر را در `BASE_URL` بگذارید و پیشوند مسیر را هنگام پراکسی حفظ کنید.

برای استقرار روی شبکه، HTTPS را روی وب‌سرور فعال کنید. فایل دیتابیس یا اطلاعات اتصال آن و کلید رمزنگاری را جداگانه و در محلی امن نگه دارید. اتصال‌های قبلی با همان کلید قابل بازیابی‌اند.

اگر نسخه قبلی با SQLite اجرا شده، می‌توانید تنظیم قبلی `DATABASE_PATH` را نگه دارید و `DB_NAME` را خالی بگذارید. هنگام تغییر به MySQL، اتصال‌های SQLite به‌صورت خودکار منتقل نمی‌شوند.

## استفاده

- هر سرویس اتصال‌های ذخیره‌شده خودش را دارد. برای ذخیره، نام و اطلاعات اتصال را وارد کنید و «ذخیره اتصال» را بزنید. فیلدهای خالی در یک اتصال موجود از مقدار ذخیره‌شده استفاده می‌کنند. کلیدها، توکن‌ها، آدرس‌ها و شناسه‌های ذخیره‌شده با AES-256-GCM رمز می‌شوند.
- در ووکامرس، آدرس HTTPS محل نصب وردپرس، کلید و رمز را وارد کنید و «تست و دریافت سفارش‌ها» را بزنید. این مسیر بدون ذخیره در دیتابیس نیز کار می‌کند. دکمه «جزئیات بیشتر» از مسیر `system_status` نسخه ووکامرس، وردپرس، PHP، حافظه وردپرس و وضعیت HTTPS را می‌گیرد. این مسیر به سطح دسترسی مشاهده وضعیت سیستم ووکامرس نیاز دارد.
- در سرویس‌های ارسال، پس از اجرای مسیرهایی مثل فهرست فروشگاه‌ها یا ثبت سفارش، شناسه‌های قابل استفاده در فرم قرار می‌گیرند. با «به‌روزرسانی اتصال» می‌توانید آن‌ها را هم ذخیره کنید. اجرای گروهی فقط مسیرهای بدون تغییر داده را پوشش می‌دهد. اجرای مستقل عملیات ثبت، لغو، ویرایش یا پرداخت می‌تواند روی سرویس واقعی اثر بگذارد.
