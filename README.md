# TapinApi

داشبورد فارسی تست API پست، تیپاکس، قطاربار و ووکامرس با یک فرانت‌اند و یک سرور. پست ۳۶ مسیر، تیپاکس ۱۸ مسیر و قطاربار ۱۵ مسیر دارند. نمونه‌های JSON از ابزارهای اولیه آمده‌اند و قبل از ارسال قابل ویرایش‌اند.

## نصب روی هاست اشتراکی

۱. فایل‌های پروژه را همراه فایل مخفی `.htaccess` در پوشه‌ای که آدرس پروژه به آن اشاره می‌کند آپلود کنید. برای نمونه، آدرس `/tapin/test/` معمولاً به پوشه `public_html/tapin/test` اشاره می‌کند. `index.php` باید در همان پوشه و کنار `public` قرار بگیرد.

۲. روی هاست، PHP نسخه ۸٫۲ یا بالاتر با افزونه‌های `pdo_mysql`، `curl` و `openssl` را فعال کنید. در Apache یا هاست سازگار با Apache، اجرای PHP، `mod_rewrite` و اعمال `.htaccess` با `AllowOverride FileInfo Indexes` لازم است. قانون قدیمی پراکسی به پورت ۳۰۰۰ را با فایل `.htaccess` این نسخه جایگزین کنید.

۳. `.env.example` را به نام `.env` در روت پروژه کپی کنید. برای نمونه اگر پروژه در `https://mahyarsalehee.ir/tapin/test` است، این مقدار را بگذارید:

```dotenv
BASE_URL=https://mahyarsalehee.ir/tapin/test/
```

۴. مقادیر `DB_HOST`، `DB_PORT`، `DB_NAME`، `DB_USER` و `DB_PASS` را از پنل هاست وارد کنید. `DB_TIMEZONE` به‌طور پیش‌فرض `+03:30` است. برنامه، جدول `profiles` را در اولین درخواست ذخیره‌سازی یا فهرست اتصال‌ها می‌سازد. برای مقدارهایی که فاصله یا نقطه‌ویرگول دارند از نقل‌قول استفاده کنید.

۵. برای فعال کردن صفحه ورود، `DASHBOARD_USER` و `DASHBOARD_PASSWORD` را تعیین کنید. رمز باید حداقل ۱۲ کاراکتر باشد. اگر `DASHBOARD_PASSWORD` خالی باشد، داشبورد و API برای هر کسی که به آدرس دسترسی دارد باز می‌شوند. اگر از نسخه فعلی MySQL استفاده می‌کنید، همان `DATABASE_KEY` قبلی را نگه دارید تا اتصال‌های ذخیره‌شده قابل خواندن بمانند. برای نصب تازه می‌توانید کلید را با PHP روی سیستم خود بسازید:

```sh
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

۶. آدرس `BASE_URL` را باز کنید. Apache از روت پروژه `index.php` را اجرا می‌کند و داشبورد و API از همان مسیر در دسترس‌اند. این نصب به Node.js یا فرایند پس‌زمینه نیاز ندارد.

## استفاده

- هر سرویس اتصال‌های ذخیره‌شده خودش را دارد. برای ذخیره، نام و اطلاعات اتصال را وارد کنید و «ذخیره اتصال» را بزنید. فیلدهای خالی در یک اتصال موجود از مقدار ذخیره‌شده استفاده می‌کنند. کلیدها، توکن‌ها، آدرس‌ها و شناسه‌های ذخیره‌شده با AES-256-GCM رمز می‌شوند.
- در ووکامرس، آدرس HTTPS محل نصب وردپرس، کلید و رمز را وارد کنید و «تست و دریافت سفارش‌ها» را بزنید. این مسیر بدون ذخیره در دیتابیس نیز کار می‌کند. دکمه «جزئیات بیشتر» از مسیر `system_status` نسخه ووکامرس، وردپرس، PHP، حافظه وردپرس و وضعیت HTTPS را می‌گیرد. این مسیر به سطح دسترسی مشاهده وضعیت سیستم ووکامرس نیاز دارد.
- در سرویس‌های ارسال، پس از اجرای مسیرهایی مثل فهرست فروشگاه‌ها یا ثبت سفارش، شناسه‌های قابل استفاده در فرم قرار می‌گیرند. با «به‌روزرسانی اتصال» می‌توانید آن‌ها را هم ذخیره کنید. اجرای گروهی فقط مسیرهای بدون تغییر داده را پوشش می‌دهد. اجرای مستقل عملیات ثبت، لغو، ویرایش یا پرداخت می‌تواند روی سرویس واقعی اثر بگذارد.
- فهرست «لیست اتصال‌ها» در سایدبار، اتصال‌های ذخیره‌شده را به تفکیک سرویس نشان می‌دهد. انتخاب هر مورد، صفحه تست همان سرویس و اتصال انتخاب‌شده را باز می‌کند.
- بدنه ویرایش‌شده درخواست‌های POST در پست، تیپاکس و قطاربار با کمی مکث خودکار ذخیره می‌شود. پیش‌نویس هر مسیر بین اتصال‌های همان سرویس مشترک است و تا زمان تکمیل JSON هم حفظ می‌شود. «بازنشانی JSON» پیش‌نویس مسیر را پاک و نمونه اصلی را بازیابی می‌کند. جدول `request_drafts` در اولین درخواست به‌صورت خودکار ساخته می‌شود و بدنه‌ها با کلید دیتابیس رمز می‌شوند.
- درخواست‌های تکیِ مسیرهای مختلف هم‌زمان قابل ارسال‌اند. اجرای گروهی مسیرها را به‌ترتیب می‌فرستد تا شناسه‌های دریافت‌شده در درخواست بعدی قابل استفاده باشند.
- «تنظیمات» در سایدبار زمان انتظار درخواست‌ها را برحسب ثانیه تعیین می‌کند. مقدار پیش‌فرض ۱۸ ثانیه است و تنظیم در همان مرورگر ذخیره می‌شود. زمان نمایش‌داده‌شده در کارت‌ها مدت درخواست HTTP است.
